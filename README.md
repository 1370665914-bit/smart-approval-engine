# 智能审批引擎（Smart Approval Engine）

> 面向财务付款与采购合同场景的**只读智能审核辅助平台**架构模板。
> 证据驱动、规则优先、模型增强、人工决策、安全闭环。

## 这是什么

一套以企业 OA 审批为入口的智能审核辅助系统的**架构与机制模板**，源自真实生产环境（2026 年 8 月运行中的实时审批辅助链路）。它把"让模型决定是否审批"的错误命题，替换为**以业务证据和确定性规则为核心、模型只做解释与编排、人工保留最终审批权**的正确架构。

## 核心设计（三个解耦 + 一个闭环）

| 原则 | 含义 |
|---|---|
| **规则与模型解耦** | 业务判断由本地确定性规则完成，模型负责解释。核心审批口径不进提示词，可独立测试与审计 |
| **事实与结论解耦** | 文档解析先形成带证据的标准事实，规则再消费事实。解析器升级不改变规则结构 |
| **输出与执行解耦** | 飞书卡片只展示建议，OA 执行能力由独立安全开关控制，默认关闭 |
| **安全闭环** | 生产门禁 + 熔断 + 幂等 + 故障分级，证据不足 fail-closed |

## 架构总览

```text
业务交互与入口层（飞书消息 / OA 待办 / 主 Agent / 专业子 Agent）
        ↓
数据连接与采集层（OA REST API / 表单字段 / 流程日志 / 附件）
        ↓
文档理解与事实层（PDF 文本 / Vision OCR / 发票解析 / 证据置信度）
        ↓
审核与决策辅助层（确定性规则 / 结构化检查 / 风险特征 / 模型解释）
        ↓
安全治理与交付层（生产门禁 / 熔断 / 幂等 / 飞书卡片 / 状态同步）
```

## Agent 协作体系

| 角色 | 职责 |
|---|---|
| 主 Agent | 任务理解、流程协调、结果整合 |
| OCR Agent | PDF、扫描件、图片文字识别 |
| 合规 Agent | 合同条款、主体、期限、合规核验 |
| 校对 Agent | 表单/合同/发票/收款信息交叉匹配 |
| Approval Agent | 审批数据结构化、调用审核引擎、生成建议 |

所有 Agent 的结论必须遵守**同一套确定性规则、证据标准和安全门禁**。

## 证据置信度体系

- `confirmed`：权威来源直接确认
- `normalized`：不改变含义的标准化
- `inferred`：由上下文推断
- `unknown`：缺失、不可读或无法确认

严格一致性规则只接受 `confirmed` 与规则允许的 `normalized` 事实。

## 故障分级（fail-closed）

`READY`（可进入正式门禁）→ `MATERIAL_MISSING`（提示补材料）→ `EVIDENCE_INSUFFICIENT`（保持未决）→ `OCR_LOW_CONFIDENCE`（转人工）→ `SYSTEM_ERROR`（停止普通结论卡）

## 快速开始（落地到你的公司）

1. 阅读 `docs/整体架构与能力说明.md` 理解设计。
2. 阅读 `docs/链路与迁移手册.md` 第 7-9 节（迁移清单与验收标准）。
3. 复制 `rules/oa-approval-rules.example.yaml` → `oa-approval-rules.yaml`，按公司制度填入实际口径。
4. 按迁移手册搭建 OA REST API 连接、本地附件解析、确定性规则与飞书卡片。
5. **保持所有自动执行开关关闭**，以 `assist` 信任等级运行，人工终审。

## 安全红线（本项目强制）

- 模型禁止改写 `pending/fail` 为 `pass`，禁止以推断替代缺失证据
- 附件正文不离开本机
- 卡片不包含通过/驳回/保存回调按钮
- 凭据、Cookie、登录态一律不进入版本库（迁移时复制模板、重新注入本机凭据）
- 生产环境默认：OA 自动操作关闭、卡片动作关闭、台账写入关闭
